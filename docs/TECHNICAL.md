# 기술 문서

## ROM 구조
- 원본은 복호화된 NCSD(`.3ds`)입니다. 파티션 0(NCCH)의 NoCrypto 플래그가 켜져 있어 그대로 읽을 수 있습니다.
- `tools/ctr.py`: NCSD → NCCH → ExeFS / RomFS(IVFC level 3) 추출.
- `tools/build.py`: RomFS 메타데이터는 그대로 두고 파일 데이터만 교체해 다시 배치한 뒤 IVFC 해시 트리, NCCH 헤더 해시, NCSD 파티션 표를 다시 만듭니다. 아무것도 바꾸지 않으면 원본 파티션과 바이트 단위로 같게 재현됩니다.
- `.code`는 표준 BLZ(역방향 LZ)로 압축돼 있습니다(`tools/codeblz.py`). 수정한 `.code`는 비압축으로 넣고 ExHeader의 압축 플래그를 끕니다.

## RomFS 파일
- 대부분 파일 이름이 경로의 CRC32(10자리 십진수)입니다. 예: `/font/font.bcfnt` → `2620443203`.
- 파일은 `blz\0` + 4바이트(정렬값) 헤더를 포함한 **파일 전체**가 표준 BLZ로 압축된 형식입니다. 앞 8바이트는 비압축 구간입니다. `none` 헤더는 비압축입니다.
- 다시 넣을 때는 압축 구간이 빈 BLZ(푸터만 있는 형태)로 감쌉니다(`tools/pack.py`). `none` 형식으로 넣으면 버퍼 정렬이 어긋나 레이아웃 텍스처가 깨집니다.
- 고속 일괄 해제: `tools/blztool` (C#).

## 메시지
- 형식(`tools/msg.py`): `00 10` + u16 개수, 이후 [u32 ID + UTF-16LE 문자열 + `00 00`] 반복, 끝에 아이콘 테이블 등 트레일러(그대로 보존).
- 제어 문자: `0x01`/`0x06`/`0x11` 색 시작, `0x05` 색 끝, `0x07`·`0x08`·`0x0B`~`0x0F` 변수 자리, `0x0D`는 줄바꿈(`\r\n`)과 변수 겸용. 번역 시 `{XX}` 형태로 바꿔 두고 개수를 검사합니다(`tools/check.py`).
- 대상 파일: `0641427059`, `3985733386`.

## 폰트(BCFNT)
- 본문 `font.bcfnt`: 셀 12×12, LA8, 256×256 시트. 바이트0 = 안티앨리어싱 강도, 바이트1 = (강도>0)×255.
- 제목용 `0520038286`: 셀 15×17, A4, 256×128 시트.
- `tools/mkfont.py`: 한자를 빼고 가나·기호·영문은 원본 글리프를 유지하며, 한글은 원본 한자와 같은 글자 상자에 렌더링합니다. CMAP은 스캔형 1개, CWDH는 단일 범위로 다시 만듭니다.

## UI 레이아웃
- `darc` 안의 BCLYT `txt1` 블록 문자열을 제자리에서 바꿉니다. 파일에 저장된 원래 문자열 길이(`txt1`+0x4C의 바이트 수) 안에서만 쓰고 길이 필드를 갱신합니다. 런타임 버퍼 길이(restrict length)만큼 쓰면 뒤 블록이 손상됩니다.

## 오프닝 동영상 (`movie/op_00.moflex`)
- 컨테이너: MOFLEX. 키프레임마다 동기 블록(`L2`) 그룹이 시작되고, 그룹 안은 [플래그][청크…]로 이뤄진 4096바이트 세그먼트입니다. 동기 세그먼트에는 키프레임 하나만 들어갑니다. 첫 그룹의 데이터 스트림(2번)은 (키프레임 번호, 타임스탬프, 동기 블록 오프셋) 인덱스입니다.
  - `tools/moflex.py`(파서), `tools/mux.py`(먹서): 원본 패킷을 넣으면 원본 파일이 바이트 단위로 같게 재현됩니다. 프레임 크기가 바뀌면 같은 규칙으로 다시 배치하고 인덱스 오프셋을 고칩니다(`tools/rebuild_mov.py`).
- 비디오: MobiClip, 400×240. `tools/mobi`(C#)에 FFmpeg `mobiclip.c` 동작을 옮긴 디코더와 트랜스코더가 있습니다.
  - 트랜스코더는 원본 비트스트림의 예측 모드·모션벡터·분할 구조를 유지하고 잔차만 다시 양자화합니다(폐루프). 자막과 무관한 블록은 원본 계수를 그대로 다시 씁니다. 원본 인코더와 같은 이스케이프 모드를 써서 비트 수도 원본과 같습니다.
  - 자막이 걸친 매크로블록은 8×8 사분면마다 원본 모션과 영모션 중 오차가 작은 쪽을 고르고, 바뀐 예측값에 맞춰 이후 모션벡터 차분을 다시 인코딩합니다.
  - 자막 두 구간(프레임 185–1080, 1503–1793)을 다시 인코딩했고, 각 구간은 키프레임 직전에 끝나므로 이후 프레임은 원본과 같습니다. 재인코딩 구간 화질은 목표 영상 대비 PSNR 약 47–54dB입니다.
- 자막 합성: 일본어 자막 페이드 구간을 프레임 단위로 지정하고(`caps.json`), YUV 평면에 흰 글자·검은 테두리를 직접 합성합니다(`tools/subs.py`, `tools/mktargets.py`).

## 검증 도구
- `tools/launch.py`, `tools/shot.py`, `tools/ctrlkey.py`, `tools/emu.py`: 포터블 Azahar를 비활성 창으로 띄우고 키 입력과 Ctrl+P(에뮬레이터 스크린샷)를 창 메시지로 보내, 사용자의 조작을 방해하지 않고 화면을 확인합니다.
- `tools/wgc`(C#): Windows Graphics Capture 창 캡처(보조).
